# 南铂封面制作台跨设备编辑体验设计

日期：2026-08-31  
状态：待用户审核  
适用范围：手机、平板、电脑浏览器中的南铂封面制作台

## 1. 目标

在不删除现有功能、不改变电脑端使用习惯、不降低导出质量的前提下，将封面制作台改造成真正适合触控设备的自适应编辑器。

核心目标：

1. 手机调整任何参数时，封面预览始终可见，不再靠猜测拖动参数。
2. 平板横屏、竖屏都能充分利用空间，不简单缩放电脑版。
3. 手机、平板、电脑共用同一套照片渲染、前后对比、涂抹溶图和导出核心。
4. 电脑端现有三栏界面与鼠标操作保持不变。
5. 新设备通过可用空间和输入能力自动适配，不依赖设备品牌或型号。

## 2. 已确认的产品决定

- 采用“自适应编辑台”，不单独维护一套手机版业务逻辑。
- 手机采用醒图式逐项调节：一级菜单、二级菜单、单项参数滑杆。
- “涂抹”是独立一级菜单。
- 手机上传照片后进入全屏编辑模式。
- 平板竖屏使用手机式结构，平板横屏使用左预览、右参数结构。
- 暂不做云同步、账号同步或手机到电脑的跨设备接力。
- 照片和编辑内容继续只在当前浏览器本地处理。

## 3. 非目标

本次不包含：

- 原生 iOS、Android 或 iPad App。
- 云端存储、账号同步、多人协作。
- 新增 AI 修图或改变现有溶图算法。
- 删除、合并或弱化现有功能。
- 重新设计电脑端视觉风格。
- 改变原图像素导出、19.9MB JPG 处理和手机内存保护规则的业务含义。

## 4. 总体架构

### 4.1 一个编辑核心，多个界面外壳

编辑能力分成两层：

1. **共享编辑核心**：管理照片、设置、文字、前后对比、涂抹记录、渲染和导出。
2. **自适应界面外壳**：根据可用空间选择电脑三栏、平板分栏或手机全屏菜单。

界面外壳只能读取和修改共享编辑状态，不能复制或重新实现渲染与涂抹算法。

建议的职责边界：

- `EditorState`：照片、文字、平台、版式、构图参数、水印、当前工具和涂抹记录。
- `RenderCore`：预览和导出的统一画面绘制。
- `RetouchCore`：笔迹、羽化、强度、遮罩擦除和主图/拍摄前目标识别。
- `ExportCore`：原图与设计图的 PNG/JPG 生成、移动端内存降级和保存流程。
- `ToolRegistry`：一级菜单、二级工具、默认值、范围、单位、复位和设备可见性。
- `DesktopShell`：现有电脑三栏。
- `CompactShell`：手机竖屏和平板竖屏的全屏编辑结构。
- `SplitShell`：手机横屏、平板横屏和较窄电脑窗口的左预览、右工具结构。

### 4.2 单一代码来源

部署页面与应用源码不能继续各自维护“看起来相同”的涂抹和导出算法。实施时应把核心逻辑收敛为一份可测试的 TypeScript 源码，再由构建流程提供给应用和静态发布页。

`docs` 中的发布文件是构建产物，不再作为另一份人工维护的业务算法来源。

## 5. 自适应布局规则

不读取 iPhone、iPad 或 Android 的设备名称。布局由编辑器容器的宽度、高度、方向和指针能力决定。

初始规则：

- **CompactShell**：小于 680 CSS px，或粗指针设备处于竖屏且宽度不足 1024 CSS px。
- **SplitShell**：680–1179 CSS px 且为横屏，或较窄的鼠标设备窗口；手机横屏高度不足时也使用紧凑分栏。
- **DesktopShell**：至少 1180 CSS px 且具备精细指针，保留现有三栏。

实际阈值应通过目标设备矩阵验证后微调，但不得按 User-Agent 写专用分支。

布局切换只能重新排版，不能重建或清空 `EditorState`。旋转设备、平板分屏和浏览器缩放后，必须保留：

- 已加载的主照片与拍摄前照片。
- 当前文字和所有参数。
- 当前一级菜单、二级工具和调整目标。
- 主照片及拍摄前照片的全部涂抹记录。
- 撤销状态和前后查看状态。

## 6. 手机全屏编辑体验

### 6.1 进入与退出

- 未上传照片时保留当前上传入口。
- 上传完成后进入全屏编辑模式，收起网站大标题。
- 顶部只保留“返回、南铂封面、导出”。
- 返回退出全屏编辑并回到原页面，但不清空当前编辑内容。
- 导出固定在右上角，点击后打开四种导出选择：原图 PNG、原图 JPG、设计 PNG、设计 JPG。

### 6.2 预览与菜单

- 封面预览固定在工具区上方。
- 页面主体不再通过长距离滚动查找参数。
- 一级菜单固定在底部，可横向滑动：照片、构图、文字、画面、涂抹、版式、更多。
- 二级菜单位于一级菜单上方，只显示当前分类的工具。
- 点击二级工具后，一次只显示一个参数滑杆、准确数值和复位按钮。
- 参数调整实时更新预览；预览与手指动作保持连续反馈。
- 工具行可以独立横向滑动，不能带动预览离开屏幕。

### 6.3 文字输入

- 点击上标题、下标题或补充小字后，在键盘上方显示当前输入框。
- 系统键盘出现时，封面预览缩成顶部小预览，但不能完全消失。
- 完成或收起键盘后，预览恢复原尺寸。
- 输入框字号不得小于 16 CSS px，避免 iOS Safari 自动放大页面。

### 6.4 安全区域

必须适配：

- iPhone 刘海、灵动岛与底部 Home 指示条。
- Safari 和 Chrome 的动态地址栏。
- Android 系统导航栏。
- 横屏设备的左右安全区。
- 屏幕键盘及其关闭动画。

顶部导出和底部一级菜单不能落入系统遮挡区。

## 7. 菜单信息架构

### 7.1 照片

- 精修图上传/更换。
- 拍摄前照片上传/更换。
- 前后对比开关。
- 安全区开关。
- 同步封面。

### 7.2 构图

- 调整对象：主照片与文字 / 拍摄前照片。
- 缩放。
- 左右位置。
- 上下位置。
- 自由旋转。
- 拍摄前智能对齐。
- 拍摄前恢复默认尺寸。

### 7.3 文字

- 上行标题、下行标题、补充小字。
- 上行、下行、小字及横线颜色。
- 上行字号、下行字号、小字大小。
- 上下行字号联动。
- 标题横线开关。
- 字体描边、字体阴影。
- 文案同步。

### 7.4 画面

- 亮度。
- 压暗强度。
- 底部向上压暗。

参数根据当前调整对象作用于主照片或拍摄前照片。

### 7.5 涂抹

- 开启/退出涂抹。
- 主照片记录 / 拍摄前记录。
- 画笔大小。
- 羽化。
- 涂抹强度。
- 涂抹前 / 涂抹后。
- 撤销一步。
- 全部清除。

### 7.6 版式

- 9 个标题位置模板。
- 抖音 9:16。
- 小红书 3:4。
- 视频号 3:4。

### 7.7 更多

- 使用、不使用、更换和移除水印。
- 水印左、中、右位置与透明度。
- 3 个记忆点的保存、应用和重命名。
- 恢复默认。
- 彻底重置。
- 长期规范说明。

## 8. 涂抹与溶图一致性

### 8.1 强制共享同一核心

手机、平板、电脑的涂抹必须使用同一个 `RetouchCore`。不允许移动端为了方便重新写一个简化画笔，也不允许只在视觉上模仿电脑端效果。

共享内容包括：

- 笔迹点采样与插值。
- 画笔大小、羽化和强度范围。
- 核心半径与模糊半径计算。
- `destination-out` 遮罩擦除与压暗层合成。
- 主照片与拍摄前照片的区域识别。
- 预览、前后查看、撤销、清除和高清导出。

### 8.2 坐标与导出

- 笔迹用归一化画布坐标保存，不依赖当前屏幕像素尺寸。
- 预览分辨率变化或设备旋转后，笔迹按同一归一化坐标重放。
- 高清导出使用同一组笔迹和同一套遮罩算法，只按导出画布比例换算。
- 预览和导出的视觉差异必须进入自动化回归测试。

### 8.3 触控状态

- 未进入涂抹时，单指拖动用于移动当前照片。
- 进入涂抹后，单指落笔用于画笔；移动照片手势暂停。
- 进入和退出涂抹必须有持续可见状态，不只依赖一次提示。
- 前后对比开启时，落笔位置继续自动识别主照片或拍摄前照片；管理记录时可明确切换目标。

## 9. 平板与电脑

### 9.1 平板竖屏

- 使用 CompactShell。
- 与手机保持相同菜单结构和操作逻辑。
- 利用更大空间增加预览尺寸和二级菜单可见项，不改变工具层级。

### 9.2 平板横屏

- 使用 SplitShell。
- 左侧固定大预览，右侧显示一级菜单、当前二级工具及参数。
- 工具区独立滚动，预览不跟随滚动。

### 9.3 电脑

- 使用 DesktopShell。
- 保留现有三栏、鼠标拖动、滚轮缩放和键盘快捷操作。
- 左右面板可以各自滚动，但不得改变中央预览尺寸或造成页面横向溢出。
- 共享核心重构完成后，电脑端导出结果必须与重构前基线一致。

## 10. 数据流与状态

1. 任一外壳中的控件向 `EditorState` 提交一个明确动作。
2. `EditorState` 更新后通知预览重绘。
3. `RenderCore` 读取同一状态生成屏幕预览。
4. 导出时 `ExportCore` 读取同一状态，并让 `RenderCore` 在目标像素尺寸重新绘制。
5. `RetouchCore` 同时服务预览和导出，不把屏幕截图放大成成品。

布局模式、面板开合和当前设备方向属于界面状态；照片参数、文字、笔迹和记忆属于编辑状态。改变界面状态不能重置编辑状态。

本期状态只存在当前浏览器内。关闭页面后的行为继续沿用现有规则，不新增云端传输。

## 11. 性能与导出质量

- 预览按屏幕尺寸选择合适的工作分辨率，保持拖动与滑杆反馈流畅。
- 高清导出继续按原始照片像素生成，不受预览尺寸影响。
- 移动端继续使用现有内存保护、候选输出尺寸和 JPG 质量尝试。
- JPG 超过限制时继续执行 19.9MB 规则，并显示实际结果或可执行建议。
- 渲染重计算应在动画帧内合并，避免每个触控事件重复创建大画布。
- 暂时不用的导出画布与对象 URL 必须及时释放。
- 开启涂抹时只更新必要遮罩，避免每次落笔重复处理无关界面。

## 12. 错误与恢复

- 照片解码失败：保留当前作品并提示更换文件。
- 拍摄前照片缺失：阻止需要该照片的对比导出，但不影响普通封面导出。
- 移动端内存不足：按现有降级策略尝试，明确显示最终像素；不能静默失败。
- 分享面板取消：保留已生成结果，允许再次导出。
- 旋转、分屏或键盘出现：不能丢失状态；若空间不足，切换外壳而不是隐藏关键操作。
- 涂抹过程中发生指针取消：结束当前笔迹并保留已完成部分，不留下永久锁定状态。
- 彻底重置：继续保留明确确认步骤，且只由“更多”中的主动操作触发。

## 13. 验收与测试矩阵

### 13.1 设备尺寸

- 320×568、375×667、390×844、430×932 手机竖屏。
- 667×375、844×390、932×430 手机横屏。
- 768×1024、834×1194、1024×1366 平板竖屏。
- 1024×768、1194×834、1366×1024 平板横屏。
- 1280、1440、1920 CSS px 宽的电脑窗口。
- 平板分屏和 680–1180 CSS px 的中间宽度。

### 13.2 浏览器与输入

- iPhone Safari。
- iPad Safari。
- Android Chrome。
- macOS Chrome 与 Safari。
- 触控、鼠标、触控板和屏幕键盘。

### 13.3 功能回归

逐项验证上传、拖入、文字、颜色、全部滑杆、9 个版式、3 个平台、水印、记忆、安全区、前后对比、智能对齐、主照片涂抹、拍摄前涂抹、撤销、清除、4 种导出和重置。

### 13.4 视觉一致性

使用固定照片、固定设置和固定笔迹，比较：

- 重构前电脑导出与重构后电脑导出。
- 同一状态在手机、平板、电脑产生的导出。
- 预览与高清导出的关键区域。
- 主照片与拍摄前照片的羽化边缘、强度和压暗层过渡。

允许由 JPEG 编码产生的轻微差异，不允许布局、笔迹位置、羽化宽度、文字位置或照片变换产生设备差异。

## 14. 实施顺序约束

1. 先冻结并记录当前电脑端视觉与导出基线。
2. 先抽取共享编辑、涂抹和导出核心，证明电脑端结果不变。
3. 再建立 ToolRegistry 和 CompactShell。
4. 完成手机全屏编辑、菜单与键盘适配。
5. 完成 SplitShell 和平板横竖屏切换。
6. 执行全部功能清单、设备矩阵和视觉一致性测试。
7. 用户在临时网页验收后才能替换正式发布页。

不得先复制一套移动端逻辑再事后尝试对齐电脑端效果。

## 15. 完成标准

同时满足以下条件才算完成：

1. 手机调节任何参数时，预览始终可见。
2. 所有现有功能在手机、平板、电脑均可到达且可用。
3. 手机和平板没有页面级横向溢出，关键按钮不被浏览器和系统安全区遮挡。
4. 旋转和布局切换不丢失任何编辑状态。
5. 涂抹和溶图在所有设备共用同一代码核心。
6. 同一状态在不同设备上的最终导出视觉一致。
7. 导出继续保持原始像素策略和现有文件大小规则。
8. 电脑端界面和工作流无回归。
9. 用户先在临时网页确认，再部署正式网页。
